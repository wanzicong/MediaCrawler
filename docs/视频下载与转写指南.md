# 视频下载与转写指南

MediaCrawler 现在可以在爬取内容元数据的同时下载视频，并使用
`faster-whisper` 生成文字稿与字幕。功能默认关闭，避免意外占用磁盘、
网络带宽和模型计算资源。

## 支持范围

- 抖音：使用流式下载、大小限制、重试、临时文件和 `ffprobe` 完整性校验。
- 小红书、Bilibili：复用原有视频下载逻辑，并将文件注册到统一媒体资产库。
- 微博：仍支持原有图片下载，不参与语音转写。
- 快手、贴吧、知乎：当前只爬取结构化数据，尚未接入视频下载。

请仅下载你有权访问和保存的内容，并遵守目标平台规则、版权要求及项目许可证。

## 命令行使用

仅下载视频：

```shell
uv run main.py --platform dy --type detail --specified_id <视频ID或URL> \
  --download_media true --headless false
```

下载后同步转写：

```shell
uv run main.py --platform dy --type detail --specified_id <视频ID或URL> \
  --transcribe_media true --whisper_model small \
  --whisper_language auto --headless false
```

`--transcribe_media true` 会自动开启视频下载。CPU 环境下 `auto` 默认使用
`int8`，检测到 CUDA 时默认使用 `float16`。第一次使用某个模型时，
`faster-whisper` 会下载模型文件；也可以通过
`config/base_config.py` 的 `WHISPER_MODEL_DIR` 指定模型缓存目录。

## 输出目录

默认目录为：

```text
data/media/{platform}/{content_id}/
├── source.mp4
├── transcript.txt
├── transcript.json
├── transcript.srt
└── transcript.vtt
```

媒体及任务状态记录在 `data/media/media_pipeline.db`。下载过程先写入
`.part` 文件，只有通过校验后才原子替换为最终视频；失败的临时文件会被清理。

可在 `config/base_config.py` 调整下载超时、重试次数、单文件大小上限和
Whisper 默认模型等参数。

## MCP 使用

所有 `crawl_{platform}` 工具新增：

- `download_media`：下载媒体，默认 `false`。
- `transcribe_media`：下载并创建后台转写任务，默认 `false`。
- `transcription_model`、`transcription_device`、
  `transcription_compute_type`、`transcription_language`。
- `word_timestamps`：是否生成词级时间戳。

MCP 转写默认异步执行。爬取响应会返回 `media_assets` 和
`transcription_jobs`，随后可调用：

- `list_media_assets`：查询媒体资产和本地路径。
- `transcribe_downloaded_media`：为已下载视频创建转写任务。
- `get_media_task_status`：查询任务的 `pending/running/completed/failed` 状态。
- `read_media_transcript`：读取 `json/text/srt/vtt` 格式结果。

MCP 只返回媒体元数据、任务状态和文字结果，不把大体积视频内容嵌入响应。

### 通过网络调用 MCP

默认启动方式仍为 `stdio`。如需使用 Streamable HTTP：

```shell
uv run python -m mcp_server --transport streamable-http
```

默认地址为 `http://127.0.0.1:8765/mcp`。监听局域网或公网地址时需要配置
`--allowed-host`，服务本身不进行应用层鉴权；详细配置和安全说明见
[`mcp_server/README.md`](../mcp_server/README.md)。
