# 视频下载与转写指南

MediaCrawler 可以在爬取内容元数据的同时下载视频，并生成文字稿与字幕。
转写功能默认关闭；开启后默认优先调用独立 Whisper HTTP API，API 不可用时
自动回退项目原有的本地 `faster-whisper`，不会删除或绕过旧实现。

## 支持范围

- 抖音：使用流式下载、大小限制、重试、临时文件和 `ffprobe` 完整性校验。
- 小红书、Bilibili：复用原有视频下载逻辑，并将文件注册到统一媒体资产库。
- 微博：仍支持原有图片下载，不参与语音转写。
- 快手、贴吧、知乎：当前只爬取结构化数据，尚未接入视频下载。

请仅下载你有权访问和保存的内容，并遵守目标平台规则、版权要求及项目许可证。

## 命令行使用

仅下载视频：

```shell
uv run main.py --platform dy --type detail --specified_id <视频ID或URL> \
  --download_media true --headless false
```

下载后同步转写：

```shell
uv run main.py --platform dy --type detail --specified_id <视频ID或URL> \
  --transcribe_media true --whisper_backend api --whisper_model small \
  --whisper_language auto --headless false
```

`--transcribe_media true` 会自动开启视频下载。CPU 环境下 `auto` 默认使用
`int8`，检测到 CUDA 时默认使用 `float16`。第一次使用某个模型时，
`faster-whisper` 会下载模型文件；也可以通过
`config/base_config.py` 的 `WHISPER_MODEL_DIR` 指定模型缓存目录。

`--whisper_backend` 支持：

- `api`：默认值。调用 OpenAI 兼容的转写 API，失败时自动回退本地模型。
- `local`：完全使用原有本地 Faster-Whisper，不调用 API。

`--whisper_model` 表示本地模型，在 `api` 模式下也是回退时使用的模型。

## API 配置

复制 `.env.example` 为 `.env`，至少填写：

```dotenv
WHISPER_BACKEND=api
WHISPER_API_BASE_URL=http://127.0.0.1:9000
WHISPER_API_KEY=替换为容器配置的密钥
WHISPER_API_MODEL=whisper-1
WHISPER_API_MODEL_VERSION=base
WHISPER_API_DEPLOYMENT_FINGERPRINT=base-auto-int8-v2
WHISPER_API_TIMEOUT=1800
WHISPER_API_FALLBACK_TO_LOCAL=true
WHISPER_API_TRUST_ENV=false
WHISPER_API_CONCURRENCY=1
```

项目启动时会自动加载根目录 `.env`。API Key 不通过 CLI、WebUI 或 MCP
参数传递，避免出现在进程命令行和日志中。

- `WHISPER_API_MODEL_VERSION` 用于记录远端实际模型并参与任务缓存。当前测试
  容器加载 `base`，因此填写 `base`。
- `WHISPER_API_DEPLOYMENT_FINGERPRINT` 描述整个远端部署；模型、默认语言、
  VAD 或解码参数变化时都必须更新，避免复用旧字幕缓存。
- `WHISPER_API_TIMEOUT` 是长视频响应等待秒数；连接失败会在约 5 秒内进入
  本地回退。
- `WHISPER_API_CONCURRENCY` 默认 `1`。当前容器内部推理串行，限制为 1 可
  避免大量 HTTP 请求在容器中堆积。
- `WHISPER_API_TRUST_ENV` 默认 `false`，本机 API 不使用系统代理；远端 API
  必须依赖 `HTTP_PROXY/HTTPS_PROXY` 时才改为 `true`。
- `http://` 只允许 `localhost` 或回环 IP。服务部署在其他电脑时必须使用
  `https://`，避免音视频和 Bearer Key 被明文传输。
- `WHISPER_API_FALLBACK_TO_LOCAL=false` 可以关闭自动回退，让 API 错误直接
  把任务标记为失败。

仅使用本地模型：

```shell
uv run main.py --platform dy --type detail --specified_id <视频ID或URL> \
  --transcribe_media true --whisper_backend local \
  --whisper_model small --whisper_language auto
```

## 输出目录

默认目录为：

```text
data/media/{platform}/{content_id}/
├── source.mp4
└── transcripts/
    └── {job_id}/
        ├── transcript.txt
        ├── transcript.json
        ├── transcript.srt
        └── transcript.vtt
```

媒体及任务状态记录在 `data/media/media_pipeline.db`。下载过程先写入
`.part` 文件，只有通过校验后才原子替换为最终视频；失败的临时文件会被清理。
每个任务使用独立目录并原子写入结果，API 重试、不同模型或并发任务不会互相
覆盖。升级前已经完成的旧任务仍可从媒体根目录读取，无需迁移文件。

转写任务额外记录：

- `requested_backend`：请求使用的后端，`api` 或 `local`。
- `actual_backend`：实际完成任务的后端；发生回退时为 `local`。
- `resolved_model`：实际记录的 API 模型版本或本地模型。
- `fallback_reason`：API 回退原因；API 成功时为空。

`transcript.json` 也包含上述信息，可以据此确认任务是否真正由 API 完成，
不能只根据 `completed` 状态判断；其中的 `job_id` 可与 SQLite/MCP 任务对应。

可在 `config/base_config.py` 调整下载超时、重试次数、单文件大小上限和
Whisper 默认模型等参数。

## MCP 使用

所有 `crawl_{platform}` 工具新增：

- `download_media`：下载媒体，默认 `false`。
- `transcribe_media`：下载并创建后台转写任务，默认 `false`。
- `transcription_model`、`transcription_device`、
  `transcription_compute_type`、`transcription_language`。
- `transcription_backend`：`api` 或 `local`，默认 `api`。
- `word_timestamps`：是否生成词级时间戳。

MCP 转写默认异步执行。爬取响应会返回 `media_assets` 和
`transcription_jobs`，随后可调用：

- `list_media_assets`：查询媒体资产和本地路径。
- `transcribe_downloaded_media`：为已下载视频创建转写任务。
- `get_media_task_status`：查询任务的 `pending/running/completed/failed` 状态。
- `read_media_transcript`：读取 `json/text/srt/vtt` 格式结果；可传
  `task_id` 精确读取某次历史任务，不传时读取该媒体的最新任务。

MCP 只返回媒体元数据、任务状态和文字结果，不把大体积视频内容嵌入响应。

`transcribe_downloaded_media` 同样提供 `backend` 参数，默认 `api`。

### 通过网络调用 MCP

默认启动方式仍为 `stdio`。如需使用 Streamable HTTP：

```shell
uv run python -m mcp_server --transport streamable-http
```

默认地址为 `http://127.0.0.1:8765/mcp`。监听局域网或公网地址时需要配置
`--allowed-host`，服务本身不进行应用层鉴权；详细配置和安全说明见
[`mcp_server/README.md`](https://github.com/NanmiCoder/MediaCrawler/blob/main/mcp_server/README.md)。
