# 抖音个人点赞与收藏

项目支持读取当前已登录抖音账号可见的点赞作品和收藏作品：

- `liked`：个人点赞作品
- `collected`：个人收藏作品

这两个能力依赖抖音 Web 端内部接口，不属于稳定的公开 OpenAPI。平台可能调整
参数、返回结构或风控策略；程序会在登录过期、业务状态异常、分页异常时以非零
状态失败，不会把未完成任务误报为成功。

抖音开放平台目前公开的用户管理能力主要返回经用户授权的 `open_id`、昵称和头像，
没有提供“当前用户点赞作品列表”或“当前用户收藏作品列表” OpenAPI。因此本功能
只能复用当前账号在抖音 Web 端的合法登录会话，不应作为稳定的官方接口依赖。

## 登录

推荐先使用二维码登录，并复用 `browser_data/` 中的本机浏览器登录态：

```powershell
uv run python main.py --platform dy --lt qrcode --type liked `
  --crawler_max_notes_count 1 --get_comment false --headless false
```

不建议在 API 或 MCP 参数中直接传组织账号 Cookie。API 与 MCP 启动的爬虫子进程
会通过临时环境变量接收 Cookie，不会把 Cookie 放进命令行或任务日志；但调用方
自身仍可能记录请求参数。

显式传入非空 Cookie 时，程序会清除该抖音浏览器上下文中的旧 Cookie，再注入并
通过“当前用户”接口验证新 Cookie，避免已有账号 A 的本地登录态覆盖账号 B。
程序会自动切换为 Cookie 登录；无效 Cookie 不会静默回退到旧账号。清理范围仅限
`douyin.com` 域，不会清除 CDP 浏览器里的其他网站 Cookie。

## CLI

```powershell
# 点赞作品
uv run python main.py --platform dy --type liked `
  --crawler_max_notes_count 100 --save_data_option jsonl

# 收藏作品
uv run python main.py --platform dy --type collected `
  --crawler_max_notes_count 100 --save_data_option sqlite

# 个人模式默认不抓评论；确有需要时显式开启
uv run python main.py --platform dy --type liked `
  --get_comment true --crawler_max_notes_count 20
```

`liked` 和 `collected` 只允许用于 `dy`，也不需要关键词、作品 ID 或创作者 ID。

## WebUI / API

WebUI 选择“抖音”后会显示 `My Likes (Douyin)` 和
`My Collections (Douyin)`。切换到其他平台时会自动恢复为搜索模式。

API 示例：

```json
POST /api/crawler/start
{
  "platform": "dy",
  "crawler_type": "liked",
  "max_notes_count": 100,
  "save_option": "jsonl"
}
```

API 默认仅监听 `127.0.0.1:8080`。如需改变监听地址，可设置
`MEDIACRAWLER_API_HOST`，但局域网或公网暴露前应增加身份认证、TLS 和访问控制。

## MCP

`crawl_dy` 工具接受：

```json
{
  "crawler_type": "collected",
  "max_notes_count": 100,
  "return_data": true
}
```

每次 `crawl_dy` 调用都会使用独立产物目录并返回 `crawl_run_id`。这保证本次列表
为空时不会读到以前任务的数据，并避免并发任务混合 `contents` 与
`user_actions`。`return_data=true` 支持 JSONL、JSON、CSV 和 Excel；也可以稍后
使用 `read_crawl_data(crawl_run_id="crawl_...")` 精确读取该次运行。
点赞和收藏模式读取时强制要求 `crawl_run_id`，防止合并不同账号的历史文件。
`read_crawl_data` 单次每类最多返回 1000 条，较大结果应直接读取隔离产物文件；
如果 JSONL 存在损坏行，工具会保留合法记录并以 `DATA_READ_ERROR` 标记部分失败，
不会把损坏文件误报为空成功。MCP 单次抓取上限为 1000 条，并会按预计分页数
扩展超时预算；需要更大批量时应拆分任务或使用 CLI/API。

SQLite、MySQL/PostgreSQL 和 MongoDB 属于共享数据库后端，MCP 可以写入，但不会
把历史库记录冒充为“本次返回数据”；这些格式需要设置 `return_data=false`。

## 输出与隐私

作品本身写入 `contents`，当前账号与作品的关系单独写入 `user_actions`：

| 字段 | 含义 |
| --- | --- |
| `account_hash` | 使用本机随机密钥对带平台命名空间的稳定 `sec_uid` 生成 HMAC，不保存原始 uid/sec_uid |
| `aweme_id` | 作品 ID |
| `action_type` | `liked` 或 `collected` |
| `observed_ts` | 本次观察到该关系的时间戳 |

CSV、JSON、JSONL 和 Excel 的个人模式文件按每次任务隔离，可作为该次任务的有限
快照。SQLite、MySQL、PostgreSQL 和 MongoDB 按
`(account_hash, aweme_id, action_type)` 去重并更新 `observed_ts`。

`CRAWLER_MAX_NOTES_COUNT` 可能让任务只读取列表前部，因此程序不会根据“本次没看
到”推断用户已经取消点赞或收藏。当前实现也不推断真实点赞时间、收藏时间或收藏
夹分组名称。

所有爬虫进程会竞争同一个本机浏览器资料锁；API、MCP 或 CLI 同时启动第二个任务
时会明确失败，而不是并发占用 `browser_data` 导致账号串用或 Chromium 锁冲突。
